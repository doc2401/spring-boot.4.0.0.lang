    Spring MVC

    Spring Boot 包含多个带有 Spring MVC 的启动器。请注意，某些启动器依赖于 Spring MVC，而不是直接包含它。本节解答关于 Spring MVC 和 Spring Boot 的常见问题。

    编写 JSON REST 服务

    任何包含在 Spring Boot 应用程序中的 Spring @RestController，只要类路径中包含 Jackson 3，默认情况下都会渲染 JSON 响应，如下面的示例所示：

    • Java

    • Kotlin

    import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class MyController {

	@RequestMapping("/thing")
	public MyThing thing() {
		return new MyThing();
	}

}
    import org.springframework.web.bind.annotation.RequestMapping
import org.springframework.web.bind.annotation.RestController

@RestController
class MyController {

	@RequestMapping("/thing")
	fun thing(): MyThing {
		return MyThing()
	}

}

    只要 Jackson 3 能够序列化 MyThing`（对于普通 POJO 或 Groovy 对象为真），则默认情况下，localhost:8080/thing 会提供其 JSON 表示。 请注意，在浏览器中，您有时可能会看到 XML 响应，因为浏览器往往会发送偏好 XML 的 accept 头。

    编写 XML REST 服务

    如果您在类路径中包含 Jackson XML 扩展（`jackson-dataformat-xml`），则可以使用它来渲染 XML 响应。之前用于 JSON 的示例同样适用。要使用 Jackson XML 渲染器，请将以下依赖添加到您的项目中：

    <dependency>
	<groupId>tools.jackson.dataformat</groupId>
	<artifactId>jackson-dataformat-xml</artifactId>
</dependency>

    如果 Jackson 的 XML 扩展不可用且 JAXB 可用，则可以使用额外的要求将 XML 渲染出来，即需要将 MyThing 注解为 @XmlRootElement，如下面的示例所示：

    • Java

    • Kotlin

    import jakarta.xml.bind.annotation.XmlRootElement;

@XmlRootElement
public class MyThing {

	private String name;

	// getters/setters ...

	public String getName() {
		return this.name;
	}

	public void setName(String name) {
		this.name = name;
	}

}
    import jakarta.xml.bind.annotation.XmlRootElement

@XmlRootElement
class MyThing {

	var name: String? = null

}

    您需要确保 JAXB 库包含在您的项目中，例如通过添加以下内容：

    <dependency>
	<groupId>org.glassfish.jaxb</groupId>
	<artifactId>jaxb-runtime</artifactId>
</dependency>
    若要使服务器渲染 XML 而非 JSON，您可能需要发送 Accept: text/xml 头（或使用浏览器）。

    自定义 Jackson JsonMapper

    您可以使用环境配置 JsonMapper。Jackson 提供了一套广泛的开关功能，可用于配置其处理的各个方面。这些功能在 Jackson 中的几个枚举中进行了描述，它们与环境中的属性相对应：

    Enum Property Values

    DateTimeFeature

    spring.jackson.datatype.datetime.<feature_name>

    true, false

    EnumFeature

    spring.jackson.datatype.enum.<feature_name>

    true, false

    JsonNodeFeature

    spring.jackson.datatype.json-node.<feature_name>

    true, false

    JsonInclude.Include

    spring.jackson.default-property-inclusion

    always, non_null, non_absent, non_default, non_empty

    DeserializationFeature

    spring.jackson.deserialization.<feature_name>

    true, false

    JsonReadFeature

    spring.jackson.json.read.<feature_name>

    true, false

    JsonWriteFeature

    spring.jackson.json.write.<feature_name>

    true, false

    MapperFeature

    spring.jackson.mapper.<feature_name>

    true, false

    SerializationFeature

    spring.jackson.serialization.<feature_name>

    true, false

    例如，要启用美化打印，请设置 spring.jackson.serialization.indent_output=true`。请注意，由于使用了宽松绑定，indent_output`的大小写不必与相应的枚举常量 INDENT_OUTPUT 的大小写匹配。

    此基于环境的配置应用于自动配置的 Builder Bean，并适用于使用构建器创建的任何映射器，包括自动配置的 JsonMapper Bean。

    为便于在使用先前采用 Jackson 2 的应用程序时进行迁移，可以配置自动配置的 JsonMapper``，使其默认值尽可能接近 Spring Boot 用于 Jackson 2 的默认值。要启用这些默认值，请将 spring.jackson.use-jackson2-defaults` 设置为 true。

    上下文的Builder可以通过一个或多个JsonMapperBuilderCustomizerbean进行自定义。这些自定义器bean可以排序（Boot 自身的自定义器顺序为 0），从而允许在 Boot 的自定义之前和之后应用额外的自定义。

    任何类型为 JacksonModule 的 Bean 都会自动注册到自动配置的 Builder，并应用于其创建的任意 JsonMapper 实例。 这提供了一种应用程序范围的机制，以便在为新应用程序添加功能时贡献自定义模块。

    参与 Java ServiceLoader` 机制的任何模块默认都会被发现并添加到自动配置的Builder中。若要禁用此行为，请将 spring.jackson.find-and-add-modules` 设置为 false。

    如果您想完全替换默认的 JsonMapper，请定义该类型的 @Bean，或者如果您更喜欢基于构建器的方法，请定义一个 Builder @Bean。 在定义一个 JsonMapper Bean 时，建议将其标记为 @Primary，因为自动配置所替换的 JsonMapper 也是 @Primary。 请注意，在这两种情况下，这样做都会禁用所有 JsonMapper 的自动配置。

    如果您提供类型为 @Bean 的 JacksonJsonHttpMessageConverter，它们将替换 MVC 配置中的默认值。 此外，还提供了一个类型为 HttpMessageConverters 的便捷 Bean（如果您使用默认的 MVC 配置，该 Bean 始终可用）。 它包含一些有用的方法，用于访问默认和用户增强的消息转换器。

    请参阅自定义 @ResponseBody 渲染部分以及 WebMvcAutoConfiguration 源代码以获取更多信息。

    自定义@ResponseBody 渲染

    Spring 使用HttpMessageConverters来渲染@ResponseBody（或来自@RestController的响应）。 您可以通过在 Spring Boot 上下文中添加适当类型的 bean 来贡献额外的转换器。 如果您添加的 bean 的类型本来就会默认包含（例如用于 JSON 转换的JacksonJsonHttpMessageConverter），它将替换默认值。 提供了一个类型为HttpMessageConverters的便捷 bean，如果您使用默认的 MVC 配置，该 bean 始终可用。 它具有一些有用的方法来访问默认和用户增强的消息转换器（例如，如果您想手动将它们注入到自定义RestTemplate中，这可能很有用）。

    与常规 MVC 用法一样，您提供的任何 WebMvcConfigurer Bean 也可以通过重写 configureMessageConverters 方法来贡献转换器。 然而，与常规 MVC 不同，您只能提供所需的额外转换器（因为 Spring Boot 使用相同的机制来贡献其默认值）。 最后，如果您通过提供自己的 @EnableWebMvc 配置来禁用 Spring Boot MVC 的默认配置，您可以完全掌控并使用 getMessageConverters（来自 WebMvcConfigurationSupport）手动完成所有操作。

    有关更多详细信息，请查看 WebMvcAutoConfiguration 源代码。

    处理多部分文件上传

    Spring Boot 采用 servlet 5 Part API 来支持文件上传。 默认情况下，Spring Boot 将 Spring MVC 配置为每个文件的最大大小为 1MB，单个请求中的文件数据最大为 10MB。 您可以使用 MultipartProperties 类中公开的属性来覆盖这些值、指定中间数据存储的位置（例如，存储到 /tmp 目录）以及指定将数据刷新到磁盘的阈值。 例如，如果您要指定文件不受限制，请将 spring.servlet.multipart.max-file-size 属性设置为 -1。

    多部分支持在希望将多部分编码的文件数据接收为 Spring MVC 控制器处理程序方法中类型为 MultipartFile 的 @RequestParam 注解参数时非常有用。

    有关更多详细信息，请参阅 MultipartAutoConfiguration 源代码。

    建议使用容器的内置多部分上传支持，而不是引入 Apache Commons File Upload 之类的额外依赖。

    关闭 Spring MVC 的 DispatcherServlet

    默认情况下，所有内容都从应用程序的根目录（`/`）提供。如果您希望映射到不同的路径，可以按如下方式配置：

    • Properties

    • YAML

    spring.mvc.servlet.path=/mypath
    spring:
  mvc:
    servlet:
      path: "/mypath"

    如果您有额外的 Servlet，可以为每个 Servlet 声明一个类型为 @Bean 的 Servlet 或 ServletRegistrationBean，Spring Boot 将透明地向容器注册它们。 也可以使用 @ServletRegistration 作为 ServletRegistrationBean 的基于注解的替代方案。 由于 Servlet 是以这种方式注册的，因此它们可以映射到 DispatcherServlet 的子上下文，而无需调用它。

    自行配置DispatcherServletPath并不常见，但如果确实需要这样做，还必须提供一个类型为DispatcherServletPath的@Bean，以提供您自定义的DispatcherServlet的路径。

    关闭默认 MVC 配置

    完全控制 MVC 配置的最简单方法是提供自己的带有 @EnableWebMvc 注解的 @Configuration。 这样做可以将所有 MVC 配置都掌握在自己手中。

    自定义 ViewResolvers

    ViewResolver 是 Spring MVC 的核心组件，负责将 @Controller 中的视图名称转换为实际的 View 实现。 请注意，视图解析器主要用于 UI 应用程序，而非 REST 风格的服务（View 不用于渲染 @ResponseBody）。 存在多种 ViewResolver 实现可供选择，Spring 本身并不主张使用哪一种。 另一方面，Spring Boot 会根据类路径和应用上下文中的发现情况，为您安装一个或两个视图解析器。 DispatcherServlet 会使用应用上下文中发现的所有解析器，依次尝试每一个，直到获得结果。 如果您添加了自己的解析器，必须注意其顺序以及它被添加到哪个位置。

    WebMvcAutoConfiguration 向您的上下文中添加了以下 ViewResolver Bean：

    • 一个名为 'defaultViewResolver' 的InternalResourceViewResolver。 该解析器通过DefaultServlet定位可渲染的物理资源（包括静态资源和 JSP 页面，如果您使用这些的话）。 它会在视图名称前后添加前缀和后缀，然后在 Servlet 上下文中查找具有该路径的物理资源（默认值均为空，但可通过spring.mvc.view.prefix和spring.mvc.view.suffix进行外部配置访问）。 您可以通过提供相同类型的 Bean 来覆盖它。

    • 一个名为 'beanNameViewResolver' 的 BeanNameViewResolver。 这是视图解析器链中一个有用的成员，它会拾取任何与正在解析的 View 名称相同的 Bean。 通常不需要覆盖或替换它。

    • 如果存在类型为 View 的 Bean，则会添加一个名为 'viewResolver' 的 ContentNegotiatingViewResolver。这是一个组合解析器，会委托给其他所有解析器，并尝试匹配客户端发送的 'Accept' HTTP 头。您可以研究一篇关于 使用视图进行内容协商 的博客文章以了解更多有关 ContentNegotiatingViewResolver 的信息，也可以查看源代码以获取详细信息。您可以通过定义一个名为 'viewResolver' 的 Bean 来关闭自动配置的 ContentNegotiatingViewResolver。

    • 如果您使用 Thymeleaf，您还有一个名为 'thymeleafViewResolver' 的 ThymeleafViewResolver。 它通过用前缀和后缀包围视图名称来查找资源。 前缀是 spring.thymeleaf.prefix，后缀是 spring.thymeleaf.suffix。 前缀和后缀的值分别默认为 'classpath:/templates/' 和 '.html'。 您可以通过提供同名的 bean 来覆盖 ThymeleafViewResolver。

    • 如果您使用 FreeMarker，您还有一个名为 'freeMarkerViewResolver' 的 FreeMarkerViewResolver。 它通过用前缀和后缀包围视图名称，在加载器路径中查找资源（该路径外部化为 spring.freemarker.templateLoaderPath，默认值为 'classpath:/templates/'）。 前缀外部化为 spring.freemarker.prefix，后缀外部化为 spring.freemarker.suffix。 前缀和后缀的默认值分别为空和 '.ftlh'。 您可以通过提供同名的 bean 来覆盖 FreeMarkerViewResolver。 可以通过定义类型为 FreeMarkerVariablesCustomizer 的 bean 来自定义 FreeMarker 变量。

    • 如果您使用 Groovy 模板（实际上，如果 groovy-templates 在您的类路径中），您还将拥有一个名为‘groovyMarkupViewResolver’的GroovyMarkupViewResolver。 它通过在视图名称周围添加前缀和后缀（外部化为spring.groovy.template.prefix和spring.groovy.template.suffix）来在加载器路径中查找资源。 前缀和后缀的默认值分别为‘classpath:/templates/’和’.tpl’。 您可以通过提供同名的 bean 来覆盖GroovyMarkupViewResolver。

    • 如果您使用 Mustache，您还有一个名为‘mustacheViewResolver’的MustacheViewResolver。 它通过用前缀和后缀包围视图名称来查找资源。 前缀是spring.mustache.prefix，后缀是spring.mustache.suffix。 前缀和后缀的值分别默认为‘classpath:/templates/’和‘.mustache’。 您可以通过提供同名的 bean 来覆盖MustacheViewResolver。

    欲了解更多信息，请参阅以下章节：

    • WebMvcAutoConfiguration

    • ThymeleafAutoConfiguration

    • FreeMarkerAutoConfiguration

    • GroovyTemplateAutoConfiguration

    自定义“白标”错误页面

    Spring Boot 安装了一个“白标”错误页面，当您在浏览器客户端遇到服务器错误时会看到该页面（使用 JSON 和其他媒体类型的机器客户端应看到具有正确错误代码的合理响应）。

    将 spring.web.error.whitelabel.enabled 设置为 false 以关闭默认错误页面。 这样做会恢复您正在使用的 Servlet 容器的默认设置。 请注意，Spring Boot 仍会尝试解析错误视图，因此您可能应该添加自己的错误页面，而不是完全禁用它。

    使用您自己的模板技术覆盖错误页面取决于所使用的模板技术。例如，如果您使用 Thymeleaf，可以添加一个 error.html` 模板。如果您使用 FreeMarker，则可以添加一个 error.ftlh` 模板。通常，您需要一个解析名为 error` 的 View，或者一个处理 /error` 路径的 @Controller。除非您替换了一些默认配置，否则应该在您的 ApplicationContext 中找到一个 BeanNameViewResolver，因此一个名为 error 的 @Bean 是实现这一目标的一种方式。有关更多选项，请参阅 ErrorMvcAutoConfiguration。

    另请参阅错误处理部分，以了解如何在 Servlet 容器中注册处理程序的详细信息。
