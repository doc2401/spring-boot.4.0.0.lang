    构建系统

    强烈建议您选择一个支持依赖管理并能消费发布到 Maven Central 仓库的构建工具。 我们推荐使用 Maven 或 Gradle。 虽然可以让 Spring Boot 与其他构建工具（例如 Ant）配合工作，但它们的支持并不完善。

    依赖管理

    Spring Boot 的每个发行版都提供一份经过精选的支持依赖列表。在实际操作中，您无需在构建配置中为这些依赖指定版本，因为 Spring Boot 会为您进行管理。当您升级 Spring Boot 本身时，这些依赖也会以一致的方式得到升级。

    如果您需要，仍然可以指定版本并覆盖 Spring Boot 的建议。

    精选列表包含了所有可与 Spring Boot 一起使用的 Spring 模块，以及经过筛选的第三方库列表。该列表以标准的物料清单（spring-boot-dependencies）形式提供，既可用于 Maven，也可用于 Gradle。

    每个 Spring Boot 发行版都关联有一个 Spring Framework 的基础版本。 我们强烈建议您不要指定其版本。

    Ant

    可以使用 Apache Ant+Ivy 构建 Spring Boot 项目。`spring-boot-antlib`“AntLib”模块也可用于帮助 Ant 创建可执行的 jar 包。

    要声明依赖项，典型的ivy.xml文件看起来如下所示：

    <ivy-module version="2.0">
	<info organisation="org.springframework.boot" module="spring-boot-sample-ant" />
	<configurations>
		<conf name="compile" description="everything needed to compile this module" />
		<conf name="runtime" extends="compile" description="everything needed to run this module" />
	</configurations>
	<dependencies>
		<dependency org="org.springframework.boot" name="spring-boot-starter"
			rev="${spring-boot.version}" conf="compile" />
	</dependencies>
</ivy-module>

    一个典型的build.xml如下所示：

    <project
	xmlns:ivy="antlib:org.apache.ivy.ant"
	xmlns:spring-boot="antlib:org.springframework.boot.ant"
	name="myapp" default="build">

	<property name="spring-boot.version" value="4.0.0" />

	<target name="resolve" description="--> retrieve dependencies with ivy">
		<ivy:retrieve pattern="lib/[conf]/[artifact]-[type]-[revision].[ext]" />
	</target>

	<target name="classpaths" depends="resolve">
		<path id="compile.classpath">
			<fileset dir="lib/compile" includes="*.jar" />
		</path>
	</target>

	<target name="init" depends="classpaths">
		<mkdir dir="build/classes" />
	</target>

	<target name="compile" depends="init" description="compile">
		<javac srcdir="src/main/java" destdir="build/classes" classpathref="compile.classpath" />
	</target>

	<target name="build" depends="compile">
		<spring-boot:exejar destfile="build/myapp.jar" classes="build/classes">
			<spring-boot:lib>
				<fileset dir="lib/runtime" />
			</spring-boot:lib>
		</spring-boot:exejar>
	</target>
</project>
    如果您不想使用 spring-boot-antlib 模块，请参阅“操作指南”中的不使用 spring-boot-antlib 从 Ant 构建可执行归档部分。

    Starters

    启动器是一组便捷的依赖描述符，您可以将其包含在应用程序中。您无需通过示例代码搜寻并复制粘贴大量依赖描述符，即可一站式获取所需的所有 Spring 及相关技术。例如，如果您想开始使用 Spring 和 JPA 进行数据库访问，请在项目中包含 spring-boot-starter-data-jpa 依赖。

    启动器包含了大量您所需依赖项，可帮助您快速启动项目，并拥有一组一致且受支持的托管传递依赖项。

    名字里有什么

    所有官方启动器都遵循相似的命名模式：spring-boot-starter-*，其中*代表特定类型的应用程序。这种命名结构旨在帮助您查找所需的启动器。许多 IDE 中的 Maven 集成允许您按名称搜索依赖项。例如，安装了相应的 Eclipse 或 Spring Tools 插件后，您可以在 POM 编辑器中按下 ctrl-space 并输入“spring-boot-starter”以获取完整列表。

    正如创建自己的 Starter部分中所解释的，第三方 Starter 不应以spring-boot开头，因为该名称保留给官方的 Spring Boot 构件。相反，第三方 Starter 通常以项目名称开头。例如，一个名为thirdpartyproject的第三方 Starter 项目通常命名为thirdpartyproject-spring-boot-starter。
