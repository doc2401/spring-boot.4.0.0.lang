    测试 Spring Boot 应用程序

    Spring Boot 应用程序是一个 Spring ApplicationContext，因此除了对普通 Spring 上下文通常所做的测试之外，无需进行任何特殊操作即可对其进行测试。

    默认情况下，Spring Boot 的外部属性、日志记录和其他功能仅在您使用 SpringApplication 创建应用程序时才会安装到上下文中。

    Spring Boot 提供了一个 @SpringBootTest 注解，当您需要 Spring Boot 功能时，它可以作为标准 spring-test @ContextConfiguration 注解的替代方案。 该注解通过 SpringApplication 创建测试中使用的 ApplicationContext 来工作，具体方式请参阅 检测配置。 除了 @SpringBootTest更具体的切片。

    如果您使用的是 JUnit 4，请别忘了在测试中也添加 @RunWith(SpringRunner.class)，否则注解将被忽略。 如果您使用的是 JUnit 6，则无需添加等效的 @ExtendWith(SpringExtension.class)，因为 @SpringBootTest 和其他 @…​Test 注解已经包含了该注解。

    默认情况下，@SpringBootTest 不会启动服务器。 您可以使用 @SpringBootTest 的 webEnvironment 属性来进一步细化测试的运行方式：

    • MOCK(默认)：加载一个 Web ApplicationContext 并提供模拟的 Web 环境。使用此注解时不会启动嵌入式服务器。如果您的类路径上不可用 Web 环境，此模式会透明地回退到创建普通的非 Web ApplicationContext。它可以与 @AutoConfigureMockMvc 或 @AutoConfigureWebTestClient 结合使用，以进行基于模拟的 Web 应用程序测试。

    • RANDOM_PORT：加载一个WebServerApplicationContext并提供真实的 Web 环境。嵌入式服务器已启动并监听随机端口。

    • DEFINED_PORT：加载一个WebServerApplicationContext并提供真实的 Web 环境。 嵌入式服务器会启动并在定义的端口（来自您的application.properties）或默认端口8080上监听。

    • NONE：使用ApplicationContext加载一个SpringApplication，但不提供任何 Web 环境（无论是模拟的还是其他的）。

    如果您的测试使用了 @Transactional，默认情况下，它会在每个测试方法结束时回滚事务。 然而，由于使用 RANDOM_PORT 或 DEFINED_PORT 这种配置会隐式提供真实的 Servlet 环境，因此 HTTP 客户端和服务器将在不同的线程中运行，从而在不同的事务中运行。 在这种情况下，服务器上启动的任何事务都不会回滚。
    @SpringBootTest 配合 webEnvironment = WebEnvironment.RANDOM_PORT，如果您的应用程序为管理服务器使用了不同的端口，则也会在一个单独的随机端口上启动管理服务器。

    检测测试配置

    如果您熟悉 Spring 测试框架，您可能习惯于使用 @ContextConfiguration(classes=…​) 来指定要加载的 Spring @Configuration。或者，您可能经常在测试中使用嵌套的 @Configuration 类。

    测试 Spring Boot 应用程序时，通常不需要这样做。每当您未显式定义主配置时，Spring Boot 的 @*Test 注解会自动搜索您的主配置。

    搜索算法从包含测试的包开始向上查找，直到找到带有 @SpringBootApplication 或 @SpringBootConfiguration 注解的类。 只要您以合理的方式结构化代码，通常就能找到主配置。

    如果您使用测试注解来测试应用程序的更具体切片，则应避免添加特定于主方法的应用程序类中某个区域的配置设置。

    `@SpringBootApplication` 底层组件扫描配置定义了用于确保切片按预期工作的排除过滤器。如果您在带有 `@SpringBootApplication` 注解的类上使用了显式的 @ComponentScan 指令，请注意这些过滤器将被禁用。如果您正在使用切片功能，请重新定义它们。

    如果您想自定义主配置，可以使用嵌套的 @TestConfiguration 类。与嵌套的 @Configuration 类不同（后者将替代应用程序的主配置），嵌套的 @TestConfiguration 类是与应用程序的主配置一起使用的。

    Spring 的测试框架会在测试之间缓存应用程序上下文。因此，只要您的测试共享相同的配置（无论其如何被发现），加载上下文的耗时过程只需发生一次。

    使用测试配置主方法

    通常，由 @SpringBootTest 发现的测试配置将是您的主要 @SpringBootApplication。 在大多数结构良好的应用程序中，此配置类还将包含用于启动应用程序的 main 方法。

    例如，以下是一个典型的 Spring Boot 应用程序中非常常见的代码模式：

    • Java

    • Kotlin

    import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class MyApplication {

	public static void main(String[] args) {
		SpringApplication.run(MyApplication.class, args);
	}

}

    • Kotlin

    排除测试配置

    如果您的应用程序使用了组件扫描（例如，如果您使用了 @SpringBootApplication 或 @ComponentScan），您可能会发现仅为特定测试创建的一级配置类意外地在所有地方被拾取。

    正如我们之前所见，@TestConfiguration可用于测试的内部类以自定义主配置。 @TestConfiguration也可用于顶级类。这样做表示该类不应被扫描选中。 然后您可以在需要的位置显式导入该类，如下例所示：

    • Java

    • Kotlin

    import org.junit.jupiter.api.Test;

import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.context.annotation.Import;

@SpringBootTest
@Import(MyTestsConfiguration.class)
class MyTests {

	@Test
	void exampleTest() {
		// ...
	}

}
    import org.junit.jupiter.api.Test
import org.springframework.boot.test.context.SpringBootTest
import org.springframework.context.annotation.Import

@SpringBootTest
@Import(MyTestsConfiguration::class)
class MyTests {

	@Test
	fun exampleTest() {
		// ...
	}

}
    如果您直接使用 @ComponentScan（即不通过 @SpringBootApplication），您需要将其与 TypeExcludeFilter 一起注册。 有关详细信息，请参阅 TypeExcludeFilter API 文档。
    导入的 @TestConfiguration 会在内部类的 @TestConfiguration 之前被处理，并且导入的 @TestConfiguration 会在通过组件扫描发现的任何配置之前被处理。 一般来说，这种顺序上的差异没有明显影响，但如果您依赖 Bean 覆盖，则需要注意这一点。

    使用应用程序参数

    如果您的应用程序期望参数，您可以让@SpringBootTest通过args属性注入这些参数。

    • Java

    • Kotlin

    import org.junit.jupiter.api.Test;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.ApplicationArguments;
import org.springframework.boot.test.context.SpringBootTest;

import static org.assertj.core.api.Assertions.assertThat;

@SpringBootTest(args = "--app.test=one")

		assertThat(args.getOptionValues("app.test")).containsOnly("one");
	}

}

    使用模拟环境进行测试

    默认情况下，@SpringBootTest 不会启动服务器，而是为测试 Web 端点设置模拟环境。

    使用 Spring MVC，我们可以使用MockMvc查询我们的 Web 端点。 可用的集成如下：

    • 使用 Hamcrest 的常规MockMvc。

    • MockMvcTester 封装了 MockMvc 并使用 AssertJ。

    • RestTestClient，其中 MockMvc 被用作处理请求的服务器。

    • WebTestClient，其中 MockMvc 被用作处理请求的服务器。

    以下示例展示了可用的集成：

    • Java

    • Kotlin

    import org.junit.jupiter.api.Test;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.resttestclient.autoconfigure.AutoConfigureRestTestClient;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc;
import org.springframework.boot.webtestclient.autoconfigure.AutoConfigureWebTestClient;
import org.springframework.test.web.reactive.server.WebTestClient;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.assertj.MockMvcTester;
import org.springframework.test.web.servlet.client.RestTestClient;
import org.springframework.test.web.servlet.client.RestTestClient.ResponseSpec;
import org.springframework.test.web.servlet.client.assertj.RestTestClientResponse;

import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.content;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

@SpringBootTest
@AutoConfigureMockMvc
@AutoConfigureRestTestClient
@AutoConfigureWebTestClient

    如果您使用来自 `spring-boot-micrometer-tracing-test` 的 @AutoConfigureTracing 或来自 `spring-boot-micrometer-metrics-test` 的 @AutoConfigureMetrics 注解 切片测试，它将自动配置一个 ObservationRegistry。

    使用指标

    无论您的类路径如何，在使用@SpringBootTest时，除了内存后端的注册表外，计量注册表均不会自动配置。

    使用追踪

    无论您的类路径如何，在使用@SpringBootTest时，报告数据的组件都不会自动配置。

    如果您需要在集成测试中使用这些组件，请使用 @AutoConfigureTracing 注解该测试。

    如果您使用 @AutoConfigureTracing 注解一个 切片测试，它将自动配置一个无操作的 Tracer。 切片测试中的数据导出不支持使用 @AutoConfigureTracing 注解。

    模拟和监视 Bean

    运行测试时，有时需要模拟应用程序上下文中的某些组件。例如，您可能拥有一个针对开发期间不可用的某个远程服务的代理。在想要模拟真实环境中难以触发的故障时，模拟也非常有用。

    Spring Framework 包含一个 @MockitoBean 注解，可用于在您的 ApplicationContext 中定义一个 Mockito mock。此外，@MockitoSpyBean 可用于定义一个 Mockito spy。有关这些功能的更多信息，请参阅 Spring Framework 文档。

    自动配置测试

    Spring Boot 的自动配置系统适用于应用程序，但在测试时有时可能过于复杂。通常，只需加载测试应用“切片”所需的配置部分即可有所帮助。例如，您可能希望测试 Spring MVC 控制器是否正确映射 URL，而不希望这些测试涉及数据库调用；或者您可能希望测试 JPA 实体，而在运行这些测试时对 Web 层不感兴趣。

    与 spring-boot-test-autoconfigure`` 结合使用时，Spring Boot 的 测试模块 包含若干注解，可用于自动配置此类“切片”。它们的工作原理相似，均提供一个 @…​Test 注解以加载 ApplicationContext，以及一个或多个 @AutoConfigure…​ 注解，可用于自定义自动配置设置。

    每个切片将组件扫描限制在适当的组件上，并加载非常有限的自动配置类集。 如果您需要排除其中之一，大多数 @…​Test 注解都提供了一个 excludeAutoConfiguration 属性。 或者，您可以使用 @ImportAutoConfiguration#exclude。
    在一个测试中使用多个 @…​Test 注解来包含多个“切片”是不支持的。 如果您需要多个“切片”，请选择其中一个 @…​Test 注解，并手动包含其他“切片”的 @AutoConfigure…​ 注解。
    也可以使用标准的 @SpringBootTest 注解配合使用 @AutoConfigure…​ 注解。 如果您不关心“切片”应用程序，但需要某些自动配置好的测试 Bean，可以使用这种组合。

    或者，可以通过在存储在 META-INF/spring 的文件中注册它们，为切片注解的任何使用添加额外的自动配置，如下例所示：

    META-INF/spring/org.springframework.boot.jdbc.test.autoconfigure.JdbcTest.imports
    com.example.IntegrationAutoConfiguration

    您可以在此文件中使用带有 # 的注释。
